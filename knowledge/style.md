"이 회사에 물어보면 되겠다"는 생각이 들어 홈페이지의 해당 페이지를 누르게 만드는 것이 목표입니다.

## 동인엔시스가 검색되게 (회사명 노출)
관련 검색어(예: "지능형 제어반", "액화수소충전소 제어", "설비 데이터 수집")로 들어온 사람이 **동인엔시스라는 회사와 하는 일**을 기억하게 합니다.
- **첫 문단 3문장 안에 '동인엔시스'를 한 번** 넣습니다. 검색 결과 미리보기에 회사명이 보입니다
- 본문에 '동인엔시스' 3~6회. 더 많으면 광고처럼 보입니다
- **회사가 무엇을 하는지 한 문장**을 꼭 넣습니다. 예: "1991년부터 부산에서 제어반을 설계·제작해 온 동인엔시스는 …". 표현은 글마다 바꿉니다 (부산 본사·양산 공장, 750건 프로젝트, 선박·수소충전소·해외 생산라인, 슈나이더 공식 SI 파트너 중 글 주제에 맞는 사실로)
- 회사명과 분야를 붙여 씁니다: "동인엔시스 지능형 제어반", "제어반 제작사 동인엔시스", "부산 제어반 업체 동인엔시스" 처럼. 사람들이 '분야 + 회사명'으로 다시 검색하게 됩니다
- 태그: `동인엔시스` + 블로그 대표 태그(지능형제어반 / 설비데이터 / 제어반제작)는 항상 넣습니다 (blogs.py)
- 사례·회사 글은 제목에 회사명을 넣어도 좋습니다. 그 밖의 글은 제목 앞쪽을 검색 키워드에 씁니다

## 말투
- "~합니다", "~입니다" 체. 현장 엔지니어가 동료에게 설명하듯 차분하고 구체적으로
- 과장 금지: "혁신적인", "최고의", "완벽한", "업계 유일" 같은 말은 쓰지 않습니다
- 어려운 용어는 처음 나올 때 한 번 풀어 줍니다. 예: "FGSS(LNG 연료를 엔진에 공급하는 설비)"
- 한 문단은 2~4문장. 모바일에서 읽기 편하게 짧게 끊습니다
- 1인칭은 "저희 동인엔시스는" 정도로만 가끔 씁니다

## 네이버 검색 노출 규칙
- 제목: 핵심 키워드를 앞쪽에. 25~40자. 낚시성 제목 금지
- 본문 길이: **공백 제외 2,500~3,500자 (기준 3,000자)** = 공백 포함 약 3,300~4,700자. 길이를 채우려고 같은 말을 반복하지 않고, 내용(배경·적용 설비·주의점·FAQ)으로 채웁니다
- 글 끝 가까이에 **자주 묻는 질문 3~5개**를 넣습니다 (질문형 검색어에 걸리고, 분량도 자연스럽게 늘어남). 형식이 Q&A형인 글은 생략
- 소제목(##) 5~8개
- 핵심 키워드는 본문에 자연스럽게 4~6회. 억지로 반복하지 않습니다
- 첫 문단 3문장 안에 "이 글에서 무엇을 알 수 있는지"를 밝힙니다
- **홈페이지 문장을 그대로 복사하지 않습니다.** 네이버는 다른 곳과 똑같은 글을 낮게 평가합니다. 사실은 그대로, 문장은 새로
- 외부 링크는 본문 끝 안내 부분에 1~2개만. 링크가 많으면 노출이 떨어질 수 있습니다
- 이미지는 글마다 **표지 1장 + 설명 이미지 2~3장 + 사진 2~3장**을 넣습니다 (아래 '이미지 규칙')
- 태그는 8~12개. 회사명 태그(동인엔시스, 지능형제어반)는 항상 포함

## 저품질 방지 규칙
- **글 형식을 돌려 씁니다.** 매일 같은 틀(도입-소제목 3개-정리-링크)이면 기계적으로 찍어낸 글로 보입니다. 아래 형식을 번갈아 씁니다
  - 해설형(개념 설명) / Q&A형(질문 5~7개에 답) / 체크리스트형(점검 항목) / 사례형(납품 실적 이야기) / 비교형(방식 A vs B) / 단계형(도입 절차) / 용어형(용어 풀이) / 현장일지형(한 현장 이야기)
  - post.json에 `"format": "해설형"`처럼 적습니다. **같은 블로그 바로 전 글과 같은 형식이면 자동 검수에서 막힙니다.** 마무리 소제목도 "정리하면"만 쓰지 말고 바꿉니다
- **다른 글과 같은 문단을 반복하지 않습니다.** 수집 항목 목록, 회사 소개 문장 등은 매번 표현을 바꾸거나 필요한 만큼만 씁니다
- **홈페이지 링크는 글당 1개.** 세 번에 한 번은 링크 없이 "블로그 상단의 홈페이지 메뉴"로 안내해도 됩니다. 연락처 줄 문구도 바꿔 씁니다
- **담당자 한마디 질문 2~3개**를 post.json `personal_prompts`에 넣습니다. 담당자가 실제 경험으로 1~2문장 덧붙이면 '직접 쓴 글'로 평가받는 데 가장 효과적입니다
- 키워드를 억지로 반복하거나, 태그를 30개씩 넣거나, 본문과 무관한 인기 키워드를 넣지 않습니다

## 자동 검수 (발행 전에 반드시 통과)
`python -m blog.generate --from-json …` 실행 시 자동으로 검사하고, 미리보기 맨 위와 이슈에 결과가 나옵니다.
- ✗(FAIL)은 고친 뒤 다시 실행합니다. ⚠(WARN)는 이유가 있으면 둬도 됩니다
- 겹침 검사: 세 블로그에 이미 발행된 글(`existing/`)과 다른 초안 전체를 비교. 20자 이상 같은 문장이 하나라도 있으면 FAIL, 본문 15% 이상 겹치면 WARN·25% 이상 FAIL
- 발행된 글 목록은 매일 작업 전에 `python -m blog.existing sync`로 새로 받습니다 (담당자가 직접 쓴 글도 비교 대상에 들어감)
- 저품질 검사: 분량, 소제목 수, 형식 돌려쓰기, 키워드 반복, 회사명 노출, 홈페이지 링크 1개, 과장 표현, AI·5% 표현, 이미지·사진 자리, 담당자 한마디
