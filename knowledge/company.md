## 지능형 제어반 (핵심 제품)
- 개념: PLC로 설비를 제어하면서 운전 데이터를 함께 수집하고, 별도 수집장비 없이 MQTT/TLS로 클라우드나 고객사 서버에 연결하는 제어반
- 수집 항목: 모터 권선온도(U·V·W), 베어링 온도, 회전속도, 전압·전류·전력량, 진동, 대기 온습도, 운전 상태신호
- 24시간 기록, 설정 기준을 벗어나면 알람
- 현장에는 제어반 1면만 설치 (별도 수집장비 불필요)
- 통신이 끊기면 제어반에 보관했다가 복구 후 오래된 순서대로 자동 재전송 (측정 시각·순번으로 중복·누락 확인)
- 상태 판정: 센서별 기준값으로 normal·warning·alarm, 센서 하나라도 경고면 설비 상태도 경고
- 데이터 제공: REST API(설비·센서 목록, 최신값, 기간 이력), WebSocket(실시간), CSV 내보내기
- 기존 타사 PLC(미쓰비시, LS, 지멘스 등)는 읽기만 함: OPC UA → Modbus TCP → 제조사 전용 프로토콜(게이트웨이) 순으로 현장에 맞게 선택
- 보안: 현장↔서버 MQTT 통신 TLS 암호화. 인터록과 최종 제어는 현장 PLC 담당, 서버는 설비를 직접 제어하지 않음. 제어망과 데이터망 분리
- 원격 접속은 고객이 승인한 VPN으로만. 제어반별 PLC 모델·버전·인증서 만료일을 대장으로 관리
- 구축 방식: 클라우드형 / 온프레미스형(고객사 서버·사내망, 외부 연결 없이 운영). 인터넷 없는 현장은 LTE 장비로 대응
- 선박용: Modicon M262 컨트롤러는 선급 상호인정 인증서 보유, 선박별 도면 승인·검사관 입회 시험
- 적용 설비: 모터로 구동되는 설비 대부분 (펌프, 송풍기, 팬, 압축기, 컨베이어, 크레인 등). 설비는 그대로 두고 제어반만 교체 또는 신규 설치
- 시작 규모: 설비 1~2대부터 단계적 확대
- AI 예지보전: 기준값 알람은 바로 사용 가능, AI 이상탐지는 PoC 단계에서 고도화 중 (※ "AI가 고장을 예측한다"고 단정하지 말 것)
- 비용: 설비 수, 모터 용량, 수집 항목, 통신 환경, 기존 제어반 교체 여부에 따라 다르며 현장 분석 후 견적 (※ 금액을 쓰지 말 것)
- 유지관리: 원격 상태 확인, 정기 점검, 알람 기준 조정, 교육, 현장 대응·부품 교체

### 도입 절차 (표준 9~15주, 현장 조건에 따라 달라짐)
1. 현장 분석 (1주): 대상 설비, 기존 제어반, 수집 포인트 확인
2. 제어반 제작 (5주): 설계·제작·배선, PLC 프로그램, 공장검사
3. 서버 구성 (2주): 암호화 연결, 데이터 저장·대시보드
4. 시운전·안정화 (2~4주): 현장 시운전, 알람 기준 설정, 운영 교육

## 산업설비 데이터 인프라 사업 (2026 보도자료 기준)
> 블로그의 최종 목적은 이 사업의 고객(제조기업)과 파트너(IT기업)를 모으는 것입니다.

- 방향: 제어반 제작사에서 **데이터 기반 DX/AX 솔루션·구독형 서비스(SaaS) 공급사**로 전환 추진
- 대표 발언(2026.10): "AI와 스마트팩토리가 제 역할을 하려면 현장 설비 데이터가 우선 확보되어야 한다" (블로그 인용 승인됨, 2026-10-13)
- 회사 발언(2026.10): "설비를 단순히 제어하는 것을 넘어, 설비 데이터를 수집·표준화하고 AI가 활용할 수 있는 제조데이터로 연결하겠다"
- 솔루션 5단계: 현장 설비(Field/Control) → 산업통신 연결(OT Connectivity) → 데이터 통합관리(Energient Industrial DataHub) → 웹 모니터링(PWA Dashboard) → AI·디지털트윈
- 지원 통신: Modbus TCP/RTU, MQTT, OPC UA
- 구축 패키지 3종: Basic, Standard, AI Advanced (가격·구성 세부는 쓰지 말 것)
- 클라우드 데이터허브에서 '설비-센서-실시간값-상태' 구조로 시계열 저장, 파트너는 REST API·WebSocket 연동
- IT기업 프로젝트가 멈추는 원인: 현장마다 다른 PLC 기종·통신 방식, 데이터 수집 게이트웨이 유지보수 부담 → 지능형 제어반이 OT 구간을 맡아 해결
- 스마트공장 공급기업 등록 완료(2026.10), 공급기업 역량진단 신청 완료
- ※ 준비 중(완료처럼 쓰지 말 것): 데이터바우처·AI바우처 공급기업 등록, M.AX 전문기업 지정, 혁신제품 지정, 스마트제조기술 전문기업 지정

### AI 예지보전·자율제어 (실증·개발 단계)
- 2026.04 고정밀 DAQ 기반 AI 예지보전 디지털트윈 솔루션 고도화·실증 착수. DAQ가 kHz 단위 전기 파형 수집, 비지도 학습 AI 분석
- AI가 찾은 최적 운전값을 현장 PLC에 되돌려 보내는 폐루프 제어 방식
- 목표: 산업용 모터 시스템 전력 소비 5% 이상 절감, "제로 다운타임" (※ 실증 결과가 아니라 **목표치**라고 반드시 밝힐 것)
- 특허 '모듈러 인출식 VFD 판넬' + AI 예지보전: 고장 징후 시 설비 전체를 멈추지 않고 해당 모듈만 교체
- 비지도 학습: 정상 운전 패턴을 스스로 학습해 미세 이상 탐지. 고장 데이터 분류가 필요 없어 데이터가 적은 신규 현장·특수 설비에도 적용 가능
- 하이브리드 구조: 무거운 학습은 클라우드, 최적화된 파라미터만 현장 엣지 컨트롤러로. 네트워크가 끊겨도 현장이 자체 판단
- 엣지 장치(ABB AC500, 피닉스컨택트 AXC F 2152)는 **검토 중** (채택 확정 아님)

## IT기업 협업
- 모델 1 OT 구간 전담: 제어반 설계·제작·설치, PLC·인버터·센서 연동, 시운전·유지보수
- 모델 2 데이터 연동: 표준 API로 MES·AI·디지털트윈 플랫폼에 설비 데이터 제공 (site_id, equipment_id, 센서별 값·단위·상태 동일 형식). 설비가 늘어도 연동 코드를 새로 만들 필요 없음
- 모델 3 공동 제안·영업: 제조 고객 공동 발굴, 정부 지원사업 공동 참여, 시연 장비 활용
- 절차: 협업 문의 → 기술 미팅(필요 시 NDA) → 시연·테스트 → 공동 프로젝트
- MQTT 토픽 구조·메시지 형식·표준 Tag 규칙은 버전 관리, 세부 문서는 NDA 후 제공
- 데이터 소유·이용 범위·보관 기간은 프로젝트별 계약으로 정함
