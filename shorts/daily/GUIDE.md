# 매일 3편 자동 기획 지침

매일 아침 예약 작업으로 새 세션이 이 파일을 읽고 숏츠 3편을 만듭니다. 사람(대표이사)은 결과물로 **타입캐스트 음성**과 **구글 플로우 사진**만 만들어 넘기면 됩니다. 합성(인포그래픽, 자막, 효과음)은 그다음 단계입니다.

## 0. 먼저 읽을 것

- `shorts/structure.md`: 제목 규칙, 6비트, 말투, 채널 규칙(법규 수치, 일반화 금지, 회사 제품). 이 규칙이 이 지침보다 우선합니다.
- `knowledge/company.md`: 회사 사실은 이 파일에 적힌 것만 씁니다.
- `shorts/daily/topics.md`: 이미 쓴 주제와 후보 주제. 겹치는 주제는 고르지 않습니다.
- 잘 된 예: `shorts/scripts/08-tunnel-lighting.md`(구성과 체크리스트), `shorts/scripts/07-airport-baggage.md`

## 1. 주제 고르기 (3편)

- 비율: 생활 전기 2편 + 현장·산업 전기 또는 제어반·데이터 1편.
- 시청자가 매일 보는 장소나 물건에 "말이 안 되는 사실"이 있는 주제를 고릅니다. 예: 낮에 더 밝게 켜는 터널, 바닥 아래 184km 길.
- 신비한 건축사전이 이미 다룬 전기 소재(양수발전, 제주 해저 송전, 산꼭대기 송전탑, 땅속 송전선 과열)는 피합니다.
- 각 주제는 마지막에 "공장 설비·제어반도 숫자로 재고 움직인다"로 한 문장 이어질 수 있어야 합니다.
- 확인 가능한 숫자가 2개 이상 나오지 않는 주제는 버리고 다른 후보로 바꿉니다.

## 2. 사실 확인

- 웹 검색으로 숫자마다 출처를 찾습니다. 공공기관 누리집, 정부 발표, 언론 보도, 논문 순으로 믿습니다. 블로그 하나만 있는 숫자는 쓰지 않습니다.
- 출처 URL, 기준 연도, 원문 표현을 체크리스트에 적습니다. 원문을 직접 확인하지 못한 숫자는 "확인 못 함"이라고 적고 쓰지 않습니다.
- 법규·기준 수치(KEC, 설계기준의 lx·cd/m², 법 조항의 주기)는 원문 조항을 확인하기 전에는 쓰지 않습니다.
- "모든", "항상", "반드시" 같은 일반화는 쓰지 않고 "어떤 곳은", "보통", "~기도 합니다"로 한정합니다.
- 회사 이름은 영상에 넣지 않습니다. "AI가 고장을 예측한다"고 쓰지 않습니다. 실적은 `company.md`에 있는 것만, 넣더라도 영상이 아니라 설명란에만.
- 계산으로 만든 비교(마라톤 4번, 1초에 28m)는 계산식을 체크리스트에 적습니다.

## 3. 대본 짜기

길이 95~100초, 내레이션 **공백 제외 600~650자**, 22~26문장. 한 문장은 한 줄입니다.

| 비트 | 시간 | 해야 할 것 |
|---|---|---|
| 1. 훅 | 0–12초 | 첫 문장은 **"여기 + 장소 + 말이 안 되는 사실 + 있습니다"**. 둘째 문장 "바로 ○○죠"에 **"여러분"**을 넣어 내 이야기로 만들고, 다섯째 문장 안에 **"대체 ~일까요?"**로 묻습니다. 가장 센 숫자를 첫 10초 안에 넣습니다. |
| 2. 균열 | 12–30초 | 상식과 어긋나는 사실과 숫자. 익숙한 크기로 비교(마라톤, 1초에 몇 m, 생수병). |
| 3. 딜레마 | 30–45초 | **"그런데 여기서 진짜 문제가 생깁니다."** 같은 중간 훅으로 시작하고, 뻔한 해법 두 개를 "~하면 되지 않냐고요?"로 묻고 왜 안 되는지 답합니다. |
| 4. 발상 전환 | 45–70초 | 훅의 질문에 답하는 문장으로 시작("그래서 ~했습니다", "그 신호는 바로 ~입니다"). "A 대신 B" 구조. 측정·센서·숫자가 나오는 자리. |
| 5. 숫자 | 70–85초 | 출처 있는 숫자 2~3개로 못 박습니다. 발표 주체와 연도를 밝힙니다. |
| 6. 지금 여기로 | 85–100초 | 데이터 연결 한 문장(예: "공장 설비도 원리는 똑같더라고요", "숫자를 남긴 쪽이 먼저 압니다"). 마지막 문장은 **첫 장면으로 돌아가** 반복 재생이 자연스럽게 이어지게 합니다. |

말투는 `structure.md` 3장(구어체, "~죠", "~거든요", 전문용어는 한 번만 쓰고 바로 풀기).

## 4. 검수 (두 번 돌리고 고칩니다)

초안을 쓴 뒤 아래를 하나씩 따져 고치고, 고친 내용을 "검수 기록" 표에 남깁니다. 두 번째 검수에서도 걸리면 다시 고칩니다.

1. 첫 문장만 듣고 넘기지 않을 만큼 궁금한가? 역설이 한 문장에 하나만 있는가? 40자를 넘지 않는가?
2. 훅의 질문에 대한 답이 비트 4 첫 문장에 분명히 나오는가?
3. 숫자마다 출처가 있고, 대본의 표현이 원문보다 세지 않은가? 연도가 오래된 숫자는 연도를 밝혔는가?
4. 일반화, 법규 수치, 회사 이름, AI 예측 단정이 없는가?
5. 같은 말(예: "그래서")이 세 번 넘게 시작에 오지 않는가? 한 문장이 60자를 넘지 않는가?
6. 공백 제외 600~650자, 22~26문장인가?
7. 마지막 문장이 첫 장면으로 돌아가는가?

## 5. 타입캐스트 대본

- 한 줄에 한 문장. 숫자는 한글로 씁니다(184 → 백팔십사, 2015년 → 이천십오 년, 46억 원 → 사십육억 원).
- 묻는 문장, 중간 훅, 답 문장을 "강조하면 좋은 곳" 표로 적습니다.
- 안내 문구: 속도는 1.0, mp3와 자막(srt)을 둘 다 내려받기.

## 6. 구글 플로우 프롬프트 (한 줄에 한 장)

플로우 에이전트가 여러 장을 한꺼번에 만들지 않는 경우가 많아서, **한 줄을 복사해 넣으면 한 장이 나오도록** 각 줄에 스타일을 다 넣습니다.

- 20~24줄. 문장마다 그림이 하나 이상 있게 하고, 클로즈업을 섞어 3~4초마다 새 그림이 나오게 합니다.
- 각 줄 형식: `NN | 장면 영어 설명. Vertical 9:16, clean 3D engineering-explainer render, soft light, slightly desaturated colors, no text, no logos, no license plates, no faces.`
- 붉은 강조가 필요한 장면만 "traced with a thin glowing red outline", "a red map pin" 등을 넣고 끝에 "only accent color glowing red"를 붙입니다. 나머지는 "No red."
- 계기판·화면·꼬리표는 "completely blank" 또는 "barcode stripes only".
- 그 아래에 장면 배치표(번호 | 대본 문장 | 합성할 때 얹을 인포그래픽과 글자)를 둡니다. 인포그래픽 그림은 따로 만들지 않습니다. 합성 단계에서 그립니다.

## 7. 파일과 커밋

  - `README.md`: 그날 3편의 제목, 한 줄 요약, 분류, 확인 못 한 점
  - `NN-slug.md` 3개: 제목·제목 후보 / 대본 표(비트·시간·화면·내레이션) / 감수 체크리스트(출처) / 검수 기록 / 타입캐스트 대본 / 플로우 프롬프트 / 장면 배치표 / 설명란
