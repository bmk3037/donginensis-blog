# 숏츠 기획 (두 단계)

`shorts/daily/GUIDE.md`를 처음부터 끝까지 읽고 그대로 따른다. 그 파일이 이 스킬보다 자세하고, `shorts/structure.md`가 그보다 우선한다.

1. **1단계:** 기획안 6개를 `shorts/daily/YYYY-MM-DD/ideas.md`(한국 시간)에 쓰고 커밋·push한 뒤, 번호·가제목·훅 첫 문장과 추천 3개를 보여 주고 "만들 3편의 번호를 알려 주세요"라고 묻고 멈춘다. 주제는 사용자가 정한다.
2. **2단계:** 사용자가 번호나 직접 낸 주제를 주면, 그 3편으로 사실 확인 → 대본 → 두 번 검수(검수 기록) → 대본 수정 → 타입캐스트 대본 → 플로우 한 줄 프롬프트·장면 배치표 → 커버 문구(머리표·큰 제목·아래 문구·배경 그림 번호)를 만든다.

꼭 지킬 것:
- **캐릭터가 스토리, 공유와 댓글, 회사 문구 없이(2026-10-24 대표이사):** 모든 편을 도감이(파란 안전모의 만화풍 현장 엔지니어) 이야기로 짜고(`shorts/characters.md`의 캐릭터판 6비트), 끝에 공유 한 문장 + 댓글 질문 한 문장. 영상·설명란에 회사 이름·슬로건을 넣지 않는다. 그림 프롬프트에는 캐릭터 시트를 참고 이미지로 붙인다.
- **주제가 정해질 때마다, 플로우 프롬프트를 쓰기 전에 반드시 스타일을 묻는다**: "건축 모형 도시 / 3D 설명 렌더 / 미니어처 디오라마"(GUIDE.md "그림 스타일 고르기", 주제에 맞는 것을 추천으로 앞에). 앞 편과 같아 보여도 생략하지 않는다(10/22 대표이사). 자동 실행이면 세 판을 모두 쓴다.
- **첫 3초가 전부다(10/23 대표이사):** 첫 문장은 3초 안(20자 안팎)에, 보는 사람 자신의 관심사(우리 집·내 돈·내 가족·내 몸)로 시작한다. 첫 장면은 이미 움직이는 클립, 0초 시작, 화면 첫 제목은 첫 문장과 같은 말. 기획안에 "첫 3초" 칸과 다른 안 2개를 적는다(GUIDE.md 3장).
- **기획할 때마다 저장·공유 장치를 넣는다(10/22 대표이사):** 기획안에 "공유 대상(보낼 그 사람 + 대본 끝 공유 한 문장)", "저장 요약(3줄, 설명란에만)", "말하고 싶은 한 가지(놀라운 숫자·비유)"를 적고, 대본 비트 6에 공유 한 문장, 설명란에 요약·질문·보낼 사람을 넣는다(GUIDE.md 1장·3장).
- 숫자마다 출처 URL·연도·원문 표현을 적는다. 못 찾은 숫자는 뺀다.
- 법규·기준 수치는 원문 조항을 확인하기 전에는 쓰지 않는다.
- "모든·항상·반드시" 같은 일반화를 쓰지 않는다.
- 회사 사실은 `knowledge/company.md`에 있는 것만 쓴다. 회사 이름은 영상에 넣지 않는다.
- "AI가 고장을 예측한다"고 쓰지 않는다.
- 브랜치는 `claude/shorts-daily`를 쓰고 PR은 만들지 않는다.
- 파일이나 커밋에 모델 이름을 적지 않는다.
- 끝나면 사용자에게 할 일을 알려 준다. 타입캐스트에 대본을 붙여 넣고 속도 1.0으로 mp3와 srt를 받는다. 플로우에는 한 줄씩 넣어 이미지를 만든다. 결과를 보내 주면 합성한다(`shorts-compose` 스킬).
